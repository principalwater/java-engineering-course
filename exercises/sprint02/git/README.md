# История Git: индекс, stash, bisect и rebase

## Цель

На небольших примерах проверить частичное индексирование, временное сохранение изменений, двоичный поиск регрессии и объединение коммитов.

## 1. Подготовка и проверки в терминале

Нужны Git и Python 3. Из этого каталога:

```sh
python3 practice.py
```

Скрипт создаёт собственные Git-данные в `target/`. Он останавливается, если каталог уже существует, чтобы сохранить предыдущие результаты. История основного репозитория курса не изменяется.

| Каталог | Выполненная операция | Проверяемый результат |
| --- | --- | --- |
| `target/partial-staging/` | `git add -p someFileName` с выбором первого hunk | Изменение начала файла в коммите; изменение конца осталось вне индекса |
| `target/stash-practice/` | `stash push`, `list`, `apply`, `drop` | Содержимое восстановлено; stash удалён, рабочее изменение сохранено |
| `target/bisect-practice/` | Пошаговый `bisect good/bad` по пяти коммитам | Найден коммит, изменивший ответ с 42 на 41; исходная ветка восстановлена |
| `target/history-practice/` | `rebase -i --root` с squash | Три корневых коммита стали одним, Git tree сохранился |

Попытка `rebase -i HEAD~3` для истории из трёх коммитов даёт ожидаемую ошибку: родителя корневого коммита нет. `--root` включает корневой коммит в последовательность. Исходная история сохранена в `archive/pre-root-squash`.

## 2. Объединение средствами IDE

В `target/history-practice/` подготовлена ветка `feature/sprint02-ide-squash`: после базового коммита сделаны три новых. Исходная ветка сохранена как `archive/pre-ide-squash`.

Откройте этот каталог отдельным проектом IntelliJ IDEA. В **Git → Log** выберите три последних коммита и выполните **Squash Commits**. Сообщение объединённого коммита: `SPRINT-02: combine IDE sample files`. Проверьте, что три новых коммита стали одним, а все три `ide-*.txt` сохранились.

До операции в ветке четыре коммита с учётом базового; после — два. Сравнить содержимое с исходным ref можно командой:

```sh
git diff archive/pre-ide-squash HEAD
git log --oneline
```

Пустой diff подтверждает сохранность файлов. Переписывается только учебная история; remotes и публикация для упражнения не нужны.

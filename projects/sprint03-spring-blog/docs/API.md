# REST-контракт · Спринт 03

Базовый адрес: `http://localhost:8080`. Успешные операции возвращают `200 OK`.

| Метод | Путь | Запрос / ответ |
| --- | --- | --- |
| GET | `/api/posts?search=&pageNumber=1&pageSize=5` | Обязательные параметры → `posts`, `hasPrev`, `hasNext`, `lastPage` |
| GET | `/api/posts/{id}` | Полный пост |
| POST | `/api/posts` | `title`, `text`, `tags` → Созданный пост, счётчики 0 |
| PUT | `/api/posts/{id}` | `id`, `title`, `text`, `tags` → Обновлённый пост |
| DELETE | `/api/posts/{id}` | Удалить пост, теги, комментарии и изображение; пустое тело |
| POST | `/api/posts/{id}/likes` | Атомарный +1 → Число в JSON |
| PUT | `/api/posts/{id}/image` | Поле multipart `image` → Пустое тело |
| GET | `/api/posts/{id}/image` | Байты изображения и фактический MIME-тип |
| GET | `/api/posts/{postId}/comments` | Массив комментариев |
| GET | `/api/posts/{postId}/comments/{id}` | Комментарий |
| POST | `/api/posts/{postId}/comments` | `text`, `postId` → Созданный комментарий |
| PUT | `/api/posts/{postId}/comments/{id}` | `id`, `text`, `postId` → Обновлённый комментарий |
| DELETE | `/api/posts/{postId}/comments/{id}` | Пустое тело |

Пост: `id`, `title`, `text`, `tags`, `likesCount`, `commentsCount`. Комментарий: `id`, `text`, `postId`. Все поля ответа обязательны. Отдельный пост возвращает полный Markdown; лента — первые 128 кодовых точек Unicode и `…`, если текст длиннее. Теги сохраняют порядок и не повторяются.

Поиск разбивает строку по пробельным символам, удаляет пустые слова и требует наличия всех точных `#тегов`. Остальные слова образуют одну подстроку заголовка без учёта регистра. `%`, `_`, `!` и кавычки ищутся буквально. Сортировка — по убыванию ID. Нумерация страниц начинается с 1, `pageSize` — 1–100. Пустой результат имеет `lastPage=1`; положительная страница за пределами списка возвращается пустой, её номер не меняется.

Отсутствующие или некорректные параметры дают `400`; отсутствующий объект или комментарий чужого поста — `404`; неподдерживаемый метод — `405` с `Allow`; слишком большой multipart — `413`; неподдерживаемый формат запроса — `415`. Ошибка: `{"error":"…"}`, без SQL и стека исключения. ID в URL и теле должны совпадать. Изображение должно быть PNG/JPEG/GIF/BMP, до 5 МиБ и 16 млн пикселей; имя файла и заявленный MIME-тип не определяют путь хранения и тип ответа.

## Расхождения с заданием

1. **Чтение поста.** Документ указывает POST; реальный `xR` в предоставленном `index-CdCwR2aM.js` вызывает `fetch(url)` без options, то есть GET. Операция не меняет состояние и соответствует [RFC 9110 §9.3.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.1). Реализован только GET; POST на этот адрес возвращает 405. Это подтверждённое расхождение источников, вероятная ошибка текста, без подтверждения намерения авторов. Возможная буквальная POST-проверка требует обсуждения с ревьюером.
2. **Редактирование комментария.** Клиентский `zR` использует `n.id` и для поста, и для комментария. При сборке заменяется только сегмент поста на `n.postId`; checksum и единственность совпадения проверяются. Бэкенд сохраняет строгий маршрут из ТЗ и проверку принадлежности.
3. **Первичная загрузка комментариев.** Эффект выполнялся до получения `postId` и не повторялся после загрузки поста. Ответ `400` с объектом ошибки попадал в состояние комментариев, после чего `comments.map` завершался исключением. Эффект теперь ждёт положительный ID и зависит от него; загрузчик проверяет HTTP-статус и массив ответа. Полная перезагрузка поста проверена в браузере: пост, изображение и комментарии возвращают `200`, запроса с неопределённым ID нет. Проверки ID на сервере сохранены.

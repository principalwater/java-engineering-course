# Iterator как реактивный источник

## Цель

Подключить обычный Iterator к Java Flow и проверить управление спросом без сторонней реактивной библиотеки.

## Описание

Java 21, Maven 3.9.16, JUnit 5.11.2. `IteratorPublisher<T>` выдаёт элементы только после положительного `request(n)`. Один Iterator обслуживает одного подписчика: повторная подписка получает `onSubscribe`, затем ошибку, сохраняя состояние первой подписки.

## Этапы выполнения

### 1. Подписка и спрос

Подписчик получает Subscription до первого сигнала данных. Спрос суммируется с насыщением до `Long.MAX_VALUE`; выдача уменьшает конечный остаток. Защита от повторного входа позволяет вызывать `request` из `onNext`, не наращивая стек.

### 2. Завершение и отмена

Исчерпание Iterator завершает поток, включая пустой источник без запроса элементов. Неположительный спрос и исключение Iterator дают один `onError`. После ошибки, завершения или `cancel` новые запросы игнорируются; отмена не порождает терминальный сигнал. Значения null запрещены контрактом Flow.

### 3. Проверка

Из корня репозитория, с JDK 21 в PATH:

```bash
./exercises/sprint01/junit5/mvnw -B --no-transfer-progress \
  -f exercises/sprint06/iterator-publisher/pom.xml verify
```

Прогон: 8 случаев, ошибок и пропусков нет. Проверены ограниченный спрос, повторный запрос на 10 000 элементах, отмена из callback, некорректный спрос, ошибка источника, повторная подписка и пустой Iterator.

Выдача синхронная: Iterator и callbacks должны быстро возвращаться. Отдельного планировщика, асинхронного I/O и полной проверки Reactive Streams TCK здесь нет; нагрузка и конкурентные вызовы не проверялись.
